# Outer folds: what `--mode folds` does and where each method comes from

Hu *et al.* 2024 evaluated every method under three fold sets per (species, antibiotic):
random, phylogeny-aware and homology-aware (KMA). Their fold files are published (Mendeley data
[10.17632/6vc2msmsxj.2](https://data.mendeley.com/datasets/6vc2msmsxj/2), and
`data/PATRIC/cv_folds/` of [AMR_benchmarking](https://github.com/hzi-bifo/AMR_benchmarking)).
`s2g2p folds` (`src/s2g2p/folds.py`) makes folds the same three ways for any cohort. This page
records what each method is based on, and how close it comes to the published files.

**To compare with the published results, use the published fold files.** None of the three can
be regenerated byte for byte, for the reasons below.

## kma: the published procedure

Source: AMR_benchmarking `AMR_software/AytanAktug/` (merge_scaffolds.py,
cluster_preparation/cluster_SSSA.sh, kma_clustering.c) and `src/cv_folds/cluster2folds.py`
(MIT; the clustering program is Apache-2.0, vendored unchanged as `envs/vendor/kma_clustering.c`).

1. Per phenotype, the labelled genomes, in sample-sheet order, are written to one FASTA: one
   record per genome, contigs joined by 16 Ns (`s2g2p kma-input`; byte-identical to
   merge_scaffolds.py, which the tests check).
2. `kma_clustering -i -- -k 16 -Sparse - -ht h -hq h -NI`, with `h` = `--kma_identity`
   (published: 0.9; 0.98 for *N. gonorrhoeae*; for *M. tuberculosis* 0.99 for amikacin,
   ethambutol, ethiomide, ethionamide, kanamycin and ofloxacin, 0.98 for the other drugs).
3. Its log gives the clusters (`read_kma_clusters`); `cluster_split` shuffles them (seed 42),
   cuts them into *k* runs, and moves clusters from the largest fold into any fold below 20%
   of the expected size. A cluster is never split, so fold sizes are uneven.

`read_kma_clusters`, `cluster_split` and the fold assembly are ports, tested against
near-verbatim copies of the published functions (`tests/test_folds.py`). One deliberate
difference: a genome kma_clustering does not report ("Too short") was silently left out of every
fold by the published code; here it becomes a cluster of its own, and `manifest.tsv` counts it
(`unclustered`).

kma_clustering is order-dependent (greedy), so the published folds come back only when the sample
sheet lists the genomes in the order of the published `Data_<species>_<antibiotic>` file, from
the same assemblies.

## phylogeny: rebuilt from what the published split is documented and observed to do

Source of the tree: AMR_benchmarking `src/cv_folds/phylo_tree.r`. Roary's core-gene alignment
(Seq2Geno's Roary, `-e --mafft`) of all genomes of the species, Hamming distances, phangorn
`NJ`, written by ape. `src/s2g2p/R/nj_tree.R` is that script, with phangorn 2.10.0 and ape 5.6-2
(the CRAN releases of 2022) pinned in `envs/folds.lock.txt`.

The split itself was made by the Geno2Pheno web server, whose code was never released; the
AMR_benchmarking code exits at that branch ("we directly provided Phylogeny folds via
Seq2Geno2Pheno"). The 2019 Geno2Pheno code on GitHub (20 spectral clusters of the tree, a held-out
test set, then `GroupKFold`) cannot produce the published folds, which have no held-out set and
exactly equal sizes. What is known:

- Supplemental Methods: Geno2Pheno "generates folds of equal size", "based on the clade structure
  of the phylogenetic tree"; "some phylogenetically close strains may be allocated into both
  training set and test set, depending on the tree structure".
- The published sizes are exactly `np.array_split`'s: 28×7 + 27×3 for *E. faecium* vancomycin
  (277 genomes), 40×5 + 39×5 for *C. jejuni* tetracycline (395).
- They ignore labels: resistant genomes per fold range from 6 to 21 (*E. faecium*), where the
  published random folds have 13-14 in every fold.
- They follow the tree. On an NJ tree of our own *E. faecium* core alignment (277 genomes, 1.28
  Mb), the minimum number of fold changes along the tree (Sankoff parsimony, root- and
  rotation-free) is:

  | Split | Changes |
  |---|---:|
  | published phylotree | 36 |
  | 10 equal blocks of our tree's leaf order | 29 |
  | published KMA | 73 |
  | published random | 203 |
  | phylotree labels permuted (mean of 20) | 204 |

So `tree_folds` takes the labelled genomes in the tree's leaf order (as written in the Newick
file) and cuts them into *k* contiguous blocks with `np.array_split`. The published folds are
consistent with this, but it is a reconstruction, not a port; the tree itself also differs from
run to run, because Roary is not deterministic.

## random

`StratifiedKFold(k, shuffle=True, random_state=--seed)` over the labelled genomes in sample-sheet
order. The published random folds were made by the Geno2Pheno server (*M. tuberculosis*: scikit-
learn `KFold`). They are stratified too (13-14 resistant genomes in every *E. faecium* fold), but
they match no `StratifiedKFold` or `KFold` over the published or the sorted genome order with
seeds 0, 1 or 42 (none shuffled, too), so the order and seed are unknown.

## Output

`<outdir>/folds/<phenotype>_<method>_cv.json` (the published format: a list of id lists, read by
`--folds`), and `manifest.tsv` with one row per file: genomes, folds, fold sizes, resistant
genomes per fold, the source (seed, tree or cluster log), and for `kma` the number of clusters
and of unclustered genomes. The tree is kept as `folds/tree/nj_tree.newick`, the cluster logs as
`folds/kma/<phenotype>.clusters.txt`.
